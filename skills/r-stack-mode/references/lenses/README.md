# Selective domain lenses

Load a lens only when its trigger changes what must be observed. Usually one is
enough; add a second only for another material boundary. These are not mandatory
phases or a second router. Do not read the whole directory before every task.

| Trigger | Lens |
| --- | --- |
| Visual design, user flows, frontend or visual parity | [UI and UX](ui-ux.md) |
| External claims, literature, market or technology comparison | [Research](research.md) |
| Persistence, retries, processes, concurrency or integration | [State and integration](state-integration.md) |
| Authorization, sensitive data or untrusted content | [Security](security.md) |
| Schema/data migration, release or deployment | [Migration and delivery](migration-delivery.md) |
| Calculations, datasets, metrics or analytical conclusions | [Data analysis](data-analysis.md) |

The lens belongs beside the selected playbook. For example, use Feature plus UI
and UX for an interface implementation, or Investigation plus Research for a
technology recommendation. Architecture and UX are not interchangeable.
