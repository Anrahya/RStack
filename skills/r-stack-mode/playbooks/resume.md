# Resume

Use first when work is interrupted, inherited, compacted, or continued from a
prior task. Resume modifies the underlying investigation, bug, feature,
refactor, performance, or operational route; it does not replace it.

1. **Recover.** Invoke `resume`. Read the latest summary or checkpoint, then
   inspect the live workspace, branch, diff, recent commits, active tasks, and
   cited artifacts.
2. **Reconcile.** Produce one checkpoint containing the original contract,
   underlying route, current gate, accepted decisions, completed and active work
   units, valid evidence, stale evidence, exact tree or live-state fingerprint,
   blockers, and next action.
3. **Avoid duplication.** Do not repeat completed investigation, reproduction,
   implementation, or proof unless current state conflicts with its receipt.
   Re-run only the evidence invalidated by later mutations or external change.
4. **Continue.** Load the underlying primary playbook and resume at its first
   unmet gate. Preserve active write ownership and stop stale lanes before
   dispatching replacements.
5. **Close.** Complete normally or return the exact resumable checkpoint. Do not
   create a repository handoff or status file unless project policy requires it.
