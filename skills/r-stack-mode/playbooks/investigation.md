# Investigation

1. **Contract.** State the question, decision criteria, relevant scope and
   read-only boundary. Identify evidence that could change the answer.
2. **Ground.** Invoke `investigate`. Trace actual mechanics for software
   behavior; use the Research lens for external literature, market or technical
   comparisons. Independent lanes must cover genuinely distinct questions.
3. **Challenge.** Test competing explanations or seek contrary primary evidence.
   Do not treat a requested diagnosis, a popular claim or several repeated
   announcements as proof. Resolve conflicting versions before comparing numbers.
4. **Synthesize.** Separate observed facts, supported inference, proposal and
   unknowns. Name inaccessible sources and material limits. Use a prototype only
   when the task authorizes the required temporary mutation.
5. **Close.** Return the answer, load-bearing evidence, rejected alternatives,
   uncertainty and the next discriminating observation. Do not silently turn a
   recommendation into implementation.
