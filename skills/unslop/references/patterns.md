# Editing patterns

Use these as diagnostics, not a forbidden-word list.

| Pattern | Useful repair | Do not lose |
| --- | --- | --- |
| Inflated vocabulary: "utilize", "facilitate" | Use the ordinary word when equally precise. | Necessary terminology and the author's voice. |
| Unsupported authority: "research proves", "experts agree" | Name an already supported source or flag the claim. | The boundary between evidence and assertion. |
| Empty framing: "it is important to note" | State the actual point. | Warnings that materially affect a decision. |
| "Not just X, but Y" everywhere | State the relationship directly. | A real contrast when it explains something. |
| Generic -ing clauses | Explain the mechanism or delete the empty clause. | Real causal relationships. |
| Repeated synonyms for one thing | Keep a stable name. | Distinctions between genuinely different things. |
| Forced groups of three or false "from X to Y" ranges | Use the natural grouping or list the topics. | Items the reader actually needs. |
| Abstract metaphor instead of mechanism | Name what acts on what. | Analogies that help a learner and are labeled as analogies. |
| Ornamental headings, bold labels and emoji | Use formatting only to help navigation. | Requested formats and appropriate expressive voice. |
| Dense noun strings or stacked clauses | Unpack the relationship or split the sentence. | Conditions, actors and causality. |
| Passive voice obscuring responsibility | Name the actor when known and relevant. | Legitimate actor-unknown statements. |
| Flattery or generic closers | Begin and end with useful content. | Tone requested for a social or persuasive artifact. |
| Repeated hedges | Keep the one that states the actual uncertainty. | Material uncertainty. |
| Clipped fragments and symbol-heavy prose | Restore articles, verbs and readable sentences. | Concision, when clarity survives it. |

## Meaning-preservation example

Before: "The implementation appears to potentially improve latency significantly,
although this has not yet been benchmarked."

After: "The change may reduce latency. It has not been benchmarked."

Not: "The change reduces latency."

Before: "Experts agree the package is secure."

Without a source, do not invent one. Flag "experts agree" as unsupported, or remove
the attributed claim when the requested edit permits that omission. Do not replace
it with "The package is secure."
